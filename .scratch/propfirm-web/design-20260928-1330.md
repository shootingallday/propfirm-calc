# Design: propfirm-calc as a web app for all your prop accounts

Generated by /office-hours on 2026-09-28, then grilled against PX Journals the same day
Status: APPROVED
Mode: Builder
Supersedes: design-20260928-1248.md

## Problem Statement

propfirm-calc is a Python library and CLI where you type every number by hand, one account at a time. People who trade prop firms run several accounts across several firms. This app lets them pick their accounts from a firm catalog, bring in their P&L by typing it or importing a CSV, and see every account on one dashboard. There's no broker connection. It's an open-source side project under Jomar's own name (shootingallday), separate from PX.

## What Makes This Cool

- **What-if slider:** drag tomorrow's P&L and every account reacts together (drawdown, daily loss, consistency, payout).
- **Payout calendar:** when each account can pay out, through whichever payout path is fastest, and how much lands each week.
- **Open catalog:** the rules for 5 firms, with sources and verified dates, fixed through GitHub issues.

## What PX Journals already has (checked 2026-09-28)

- The firm catalog: `shared/src/seed/plans.ts` (2,830 lines, 26 firms). For each stage it records what consistency is measured against, what breaking it does, whether the best day resets after a payout, the other payout paths, and sources. There are 36 firm research docs.
- CSV parsers: `engine/src/imports/layouts.ts` (Tradovate Fills, TopstepX Orders), plus a list of refused exports with messages telling the user which export to use instead.
- Fills to trades: `engine/src/pairing/pair.ts` (467 lines), which uses `contracts.ts`, `session.ts` (CME trading day), the fee schedule, and `decimal.js`.
- The repo is private (`shootingallday/px-journals-prod`) and the product is paid (Stripe).

## Decisions

| # | Decision | Why |
|---|---|---|
| 1 | Static web app, installable (PWA). Accounts are saved in the browser. No server, no login, no Electron. | Nothing needs native code or a backend. It's free to host. |
| 2 | Hosted on Vercel (Hobby) or Jomar's own domain, decided at deploy time. Starts on the free subdomain. | Vercel Hobby covers a non-commercial open-source tool. |
| 3 | Branded under Jomar's own name (shootingallday), separate from PX. The npm name `propfirm-calc` is free (404 on 2026-09-28). | Jomar's call. |
| 4 | TypeScript is the only core. The monorepo has `packages/core` (math, catalog, CSV, pairing; on npm with `npx propfirm-calc`) and `apps/web` (Vite + React). pnpm workspaces. | One place for the math. PX is TS too. |
| 5 | Python package: one last PyPI release pointing to the new home, then archive. The current Python tests become the expected answers for the port. | No two copies of the math. |
| 6 | Delete the MkDocs site. The npm README documents the core, and the app explains itself. | It documents a package being retired. |
| 7 | Catalog: **Topstep, Tradeify, Lucid, My Funded Futures, Take Profit Trader**, all stages and sizes, copied from PX into this repo as JSON. | Jomar's pick. Apex dropped. |
| 8 | Catalog upkeep: rule reports come in as GitHub issues. Jomar updates this repo whenever he updates the PX catalog, using a small export script in PX so it's one command. | PX's review pipeline stays the one place rules are checked. |
| 9 | Consistency math covers every variant in the PX catalog: what it's measured against (profit target, all profit since the start, or profit since the last payout), what breaking it does (raises the target, blocks the payout, nothing), and whether the best day resets or carries after a payout. Daily loss limits too. | The Python library has only one formula and no daily loss limit. |
| 10 | CSV import supports every export from both platforms: Tradovate Fills, Balance History, Performance and Cash History, and TopstepX Orders and Trades. Fills and orders get paired into trades by porting PX's pairing code into the public core. | Jomar wants all of them. This makes the pairing code public. |
| 11 | Every account has a fee per contract per side, filled in from the firm where we know it and editable. It's used when pairing fills. | Fills without fees overstate P&L, so the floor and consistency would come out wrong in the trader's favor. |
| 12 | `decimal.js` for money everywhere in the core. | Pairing already needs it. Mixing it with floats drifts a cent at a time. |
| 13 | One P&L per account per trading day. A new import or manual edit replaces the days it covers and says which days it replaced. | Overlapping imports would count days twice. |
| 14 | The first time an import names an account (`_accountId` / `AccountName`), the user matches it to a picked account or adds one. The match is remembered. | One file can hold several accounts. |
| 15 | Payouts come from a Cash History import or from marking them by hand. They reset consistency and the payout cycle where the firm's rules say so. | Profit since the last payout needs to know when that payout was. |
| 16 | When a firm has several payout paths (like Topstep XFA's Standard and Consistency paths), work out every one and show the fastest with its name. | That's the answer the trader actually wants. |
| 17 | The slider applies the same dollar amount to every account, with a toggle per account to leave one out. | That's how a copier works. One slider is the point. |
| 18 | The calendar's average day is filled in from the imported average winning day, can be edited, and is labeled "assumes every day is a +$X day". | The projection is an optimistic lower bound. Say so. |
| 19 | Each stage is its own account. When an eval passes, the app offers "add the funded account" with the rules filled in. | No hidden stage changes. |

## Non-goals

- Broker connections (OAuth, CID, API keys).
- Monte Carlo or any simulation. That logic goes to PX Journals.
- Sign-in, cloud sync, or a server.
- Firms beyond the 5 above until someone asks through an issue.
- Electron or any native desktop build.

## Account flow

1. **Pick** the firm, the stage and the size. The rules fill in from the catalog, showing the source and the verified date.
2. **Fill in the P&L:** type daily P&L or summary fields, or drop in any supported Tradovate or TopstepX CSV.
3. **Override** any rule or the fee. The account keeps its own copy of the rules, recording which catalog version it came from.
4. **Dashboard:** every account's cushion, daily loss room, consistency and payout path, plus the slider and the calendar.
5. **Export and import** all accounts as one JSON file.

## Success Criteria

- Someone picks 3 accounts at 2 firms, imports or types their P&L, and sees one dashboard in under 2 minutes, with no signup.
- Every Python test case gives the same answer in the TS core.
- Each supported export parses Jomar's real sample files with no errors, and P&L from fills matches the platform's own P&L export for the same days, fees included.
- The slider moves every included account, and the numbers match the core.
- The site installs as a PWA and works offline.
- One Playwright run picks accounts, imports sample CSVs, moves the slider, opens the calendar, and saves screenshots plus a trace as the proof.
