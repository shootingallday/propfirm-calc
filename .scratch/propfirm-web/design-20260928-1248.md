# Design: propfirm-calc as a web app for all your prop accounts

Generated by /office-hours on 2026-09-28
Status: APPROVED
Mode: Builder

## Problem Statement

propfirm-calc is a Python library and CLI where you type every number by hand, one account at a time. People who trade prop firms run several accounts across several firms. They want to pick their accounts once and see all of them together. Nobody should have to connect Tradovate or hand over a CID to do it. It's an open-source side project meant to show people.

## What Makes This Cool

- **What-if slider.** Drag tomorrow's P&L and watch every account react. Consistency breaks on one, a payout unlocks on another, a third blows. The free calculators out there only check one account at a time.
- **Payout calendar.** When each account can pay out at your average day, and how much money lands each week.
- **Open firm-rules catalog.** Firm and account rules as data in the repo. Every entry carries a source link and a verified date, and people fix rules by sending a PR. Closed trackers like Prop Desk, TradesViz and TradeZella can't copy that.

## Constraints

- Open source; there's no plan to charge.
- Free hosting only. Nothing costs money to run.
- No broker connection. Accounts are picked from the catalog, and their numbers come from manual entry or a CSV import.
- The Monte Carlo logic stays out. It goes to PX Journals later, and this project has nothing to do with PX.

## Premises (agreed; the user left the calls to me)

1. Static web app. Accounts are saved in the browser, with no server, no login and no database.
2. No Electron. An installable web app (PWA) gets its own window and works offline, without a 100MB+ download or code-signing work.
3. The catalog is data (`firms/*.json`). Each entry has `source` and `verifiedAt`. The app shows how old the data is, and a user can override any rule on their own account.
4. Consistency varies by firm: net vs. winning-days-only, reset after each payout, and which stages it applies to. The catalog names the variant and the math supports each one.
5. Deterministic math and what-if only. No simulation.

## Approaches Considered

- **A: Port the math into the app, keep Python on PyPI.** Ruled out because the math would exist twice and drift apart.
- **C: Run the Python in the browser with Pyodide.** Ruled out because of the heavy first load (~10 MB, my estimate) for an app that should open fast.

## Recommended Approach: B, TypeScript becomes the only core

- One repo, two packages:
  - `packages/core`: the math (drawdown, consistency, payout, sizing, projection), the firm catalog and the CSV parsers. Published to npm, with a `npx propfirm-calc` CLI that matches today's commands.
  - `apps/web`: Vite + React static PWA that uses `core`.
- Python package: one last PyPI release whose README points to the new home, then archive. No two copies of the math.
- The current Python tests become the expected answers for the port. Every case has to produce the same result.

## Account flow

1. **Pick** firm, then program/stage, then size (e.g. Topstep, XFA, 50K). The rules fill in from the catalog.
2. **Fill in state** in one of two ways:
   - Manual: a daily P&L list (the app works out best day, total, winning days and peak), or summary fields.
   - CSV import: a trade or daily export from the platform.
3. **Override** any rule on this account. The account keeps its own copy of the rules and records which catalog version it came from.
4. **Dashboard**: every account's cushion to its floor, consistency state and payout status, plus the what-if slider and the payout calendar.
5. **Export/import** a JSON file of all accounts, since everything lives in one browser.

## Distribution Plan

- Web: Cloudflare Pages free plan, on your domain. It doesn't meter static bandwidth and allows 500 builds a month (third-party write-ups, 2026; check against Cloudflare's pricing page when deploying). Vercel Hobby works too, but it caps at 100 GB a month.
- Deploy on push to `main` through Cloudflare's GitHub integration or a GitHub Action.
- npm: publish `core` from the existing `release.yml`, switched from PyPI to npm.
- Docs: the current MkDocs Pages site either moves to the web app's `/docs` or points there. See the open questions.

## Open Questions

- **Which firms at launch?** Suggest Topstep, Apex, Lucid, Tradeify, Take Profit Trader, MFFU. Seed from powerFC/propfirm-rules-dataset (12 firms, 26 plans) and check each entry against the firm's own rules page.
- **Which CSV formats first?** Tradovate, NinjaTrader and Rithmic (R Trader) are the likely three. You need sample exports from your own accounts.
- **Rules the math can't handle yet:** daily loss limit (not in the library today), consistency variants, payout-cycle resets, and payout caps and splits. Each one needs a spec before the port starts.
- **Package and domain name:** `propfirm-calc` on npm and which domain.
- **Docs site:** keep MkDocs for the npm package, or fold it into the app.

## Success Criteria

- Someone picks 3 accounts from 2 firms, pastes or imports their P&L, and sees all three on one dashboard in under 2 minutes, with no signup.
- The slider moves every account at once, and the numbers match the core math.
- The payout calendar shows a date per account and a weekly total.
- Every catalog entry has a source link and a verified date, and the app shows it.
- The site installs as a PWA and works offline.
- An E2E run (Playwright) picks accounts, imports a sample CSV, moves the slider and saves screenshots as proof.
